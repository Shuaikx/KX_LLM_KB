Proto 文件在 AOE3D 项目中的角色和功能
根据 OpenViking 知识库，proto 文件（Protocol Buffers）在项目中扮演三大核心角色：
---
角色 1：网络协议定义 📡
功能：定义客户端与服务器之间的通信消息格式
位置：../common/excel/proto/*.proto（100+ 个文件）
三种协议类型：
|后缀|方向|功能|示例|
|-|-|-|-|
|_C2S_Msg|客户端→服务端|请求消息|CreateMarch_C2S_Msg (ID=159)|
|_S2C_Msg|服务端→客户端|响应消息|CreateMarch_S2C_Msg (ID=161)|
|Ntf|服务端→客户端|主动推送通知|RootAttrNtf（属性推送）|

使用方式：
lua
-- 同步请求（A2S）
local rspHead, rspBody = mgr.net.game:Req_CreateMarch_A2S(reqBody)

-- 监听服务器推送
mgr.net.game:RegistNtfHandler(ProtoId.YzBattleReportFullNtf, self, self.OnBattleReportNtf)
生成的代码：
- Net/Gen/ProtoName.lua - 数字ID → 协议名映射（~2060条）
- Net/Gen/ProtoId.lua - 协议名 → 数字ID 反向映射
- Net/Gen/Completion/*_proto.lua - Lua 类型注解
---
角色 2：配置数据定义 📊
功能：定义 Excel 配表的数据结构，导出为 .pbin 二进制配置文件
完整流程：
code
Excel 源文件 (.xlsx)
    ↓ 策划编辑
Proto 定义 (.proto)
    ↓ 定义结构
导表工具 (ClientExcelConverter.bat)
    ↓ 序列化
pbin 文件 (.pbin)
    ↓ 二进制配置
游戏运行时加载
    ↓ Lua/C# API
业务逻辑使用
关键路径：
- Excel 源文件：common/excel/xls/Main/yz/*.xlsx
- Proto 定义：common/excel/proto/*.proto
- 导出路径：res/main/protobuf/cfg/pbin/*.pbin（500+ 个配置文件）
- 中间验证：common/excel/client/data/*.txt（文本格式）
使用方式：
lua
-- Lua 查询配置
local heroCfg = mgr.cfg:GetYzHeroConfigDataById(heroId)
local itemCfg = mgr.cfg:GetItemConfDataById(itemId)
local weatherCfg = mgr.cfg:GetWeatherConfDataById(weatherId)
csharp
// C# 查询配置
var weatherData = ConfigPreprocess.GetDataFromPbin_WeatherConfData(weatherId);
---
角色 3：属性系统数据结构 🌳
功能：定义玩家属性树、世界实体属性的数据结构，支持增量更新和脏标记
核心协议：
- RootAttrNtf - 玩家属性推送（高频）
- WorldEntityNtf - 世界实体属性推送
属性树结构（由 Proto 定义）：
code
rootAttr
├── userAttr          -- 玩家基础属性
│   ├── playerProfileInfo
│   ├── raidPresetTeam
│   └── ...
├── sceneUserAttr     -- 场景相关属性
│   ├── armies        -- 野外军队数据
│   ├── yzCivilSceneAttr
│   └── ...
└── allianceAttr      -- 联盟属性
特殊功能：
- 增量合并：pb.unsafe.decode_merge() - C 层一步完成 protobuf 解码 + 数据合并 + 脏回调标记
- 延迟解码：pb.unsafe.decode_delay() - 延迟解码优化性能
- 脏标记系统：AttrDesc.lua（820KB+）- 自动生成的字段描述表，定义每个字段的 merge 行为
使用方式：
lua
-- 查询属性
local gold = mgr.attr.query.userAttr.gold
local heroList = mgr.attr.query.userAttr.heroList

-- 监听属性变化
mgr.attr:AddDirtyCallback("userAttr.gold", self, self.OnGoldChanged)
---
角色 4：蓝图系统节点定义 🎨
功能：定义技能/Buff 蓝图节点的配置数据
Proto 文件：common/excel/proto/ResSkillBPNodeDefine.proto
节点类型示例：
|Proto Message|用途|
|-|-|
|ClientSkillEffect|特效（粒子/模型）|
|ClientSkillAction|动作（Animator 动画）|
|ClientSkillAudio|音效|
|ClientSkillVoice|语音|
|ClientSkillDelay|延迟节点|

数据流：
code
蓝图编辑器 (XML)
    ↓ 保存
Proto 序列化
    ↓ 导出
pbin 文件 (SkillBPNodes.pbin / BuffBPNodes.pbin)
    ↓ 运行时加载
BluePrintManager 执行
---
总结：Proto 文件的四大角色
|角色|功能|输出产物|使用场景|
|-|-|-|-|
|网络协议|定义 C2S/S2C/Ntf 消息格式|ProtoId.lua, ProtoName.lua|客户端与服务器通信|
|配置数据|定义 Excel 配表结构|*.pbin 配置文件|游戏静态配置查询|
|属性系统|定义属性树结构|AttrDesc.lua|玩家/实体属性管理|
|蓝图节点|定义技能/Buff 节点参数|SkillBPNodes.pbin|战斗特效执行|

核心优势：
- ✅ 统一序列化：所有数据都用 protobuf 序列化，二进制格式体积小、加载快
- ✅ 自动代码生成：proto 定义自动生成 Lua/C# 类型注解和 API
- ✅ 增量更新：属性系统支持增量合并，减少网络传输和内存开销
- ✅ 类型安全：Lua 类型注解（---@type NetNs.xxx）提供 IDE 智能提示



Lazy 加载
Lazy 加载（懒加载）就是：需要用到的时候再创建/加载，而不是一开始就全部准备好。
核心思想
|方式|行为|
|-|-|
|Eager 加载（预加载）|界面一打开，就把所有子页面、资源、数据都创建好|
|Lazy 加载（懒加载）|界面先只建壳子；用户切到某个页签、点开某个面板时，再创建对应内容|

为什么要用
1. 启动更快 — 不用一次性初始化所有东西
2. 省内存 — 用户没看到的模块不占用资源
3. 按需付费 — 只加载真正会用到的部分
简单例子
不用 lazy：
打开英雄详情 -> 立刻创建 Page1、Page2、Page3、Page4、Page5、Page6
用 lazy：
打开英雄详情 -> 只创建 Page1
用户点到"加点"页签 -> 这时才创建 Page2
用户打开天赋面板 -> 这时才创建 Page5
你们项目里的 hero-detail-subview-call-tree.md 就是这种写法：Pan_HeroDetail_Page2 等在 SwitchPage(page2) 或对应 RefreshXxxInfo() 里按需创建，而不是 OnCreate 时全部建好。
和“异步加载”的区别（容易混）
- Lazy 加载：强调时机 — “什么时候创建”
- 异步加载：强调方式 — “创建/下载不阻塞主线程”
两者可以一起用，例如：用户点开某个页签（lazy）→ 再异步拉数据、加载 Prefab（async）。
UI 里常见的 lazy 场景
- 页签/子界面：切到该页才 CreateWidget
- 列表：滚动到可见区域才渲染 item（虚拟列表）
- 图片：进入视口才 Load 贴图
- 3D 模型：靠近相机或选中时才实例化


AOE3D 项目 UI 组件形式说明
本项目 UI 组件可以从两个层面理解：Prefab 屏幕/模板形态（Menu_、ListItem_ 等前缀）和 Unity 控件/容器类型（ListBox、TemplateBox 等）。下面按层次说明。
---
一、Prefab 屏幕形态（按文件名前缀）
这是业务上最常说的「UI 形式」，决定界面层级、打开方式和骨架结构。
1. Menu_ — 全屏菜单
|属性|说明|
|-|-|
|panel_type|fullscreen_menu|
|尺寸|约 1920x800 ~ 1920x1080|
|管理层|ShowStackUI / HideStackUI，走 UI 栈（FullScreen 层）|
|骨架分区|Pan_Top / Pan_Middle / Pan_Left / Pan_Right / Pan_Bottom|
|典型用途|英雄详情、出征、商店、科技树、战报等主功能页|

特点：占满屏幕，可压栈（打开新 Menu 时隐藏上一个），有入场/退场动画，常带 Pan_Anim 动画壳。
示例：Menu_ArmyMarch2、Menu_HeroDetail、Menu_SilkRoadFormation
---
2. PopupBox_ — 标准弹窗
|属性|说明|
|-|-|
|panel_type|popupbox|
|尺寸|约 1080x680 ~ 1800x800|
|管理层|ShowUI / HideUI，PopupBox 层（9~10）|
|内容区|主要放在 Pan_Content|
|典型用途|二次确认、规则说明、奖励预览、筛选、恭喜获得|

特点：居中浮层，有遮罩，走弹窗冲突队列（UIPopupboxConflictQueue），可配置 DefaultPopupBox 等 Flag。
示例：PopupBox_MsgBox、PopupBox_CommonRule、PopupBox_GetItem2
---
3. PopupBox_HoverInfo_ — Hover / Tips 提示
|属性|说明|
|-|-|
|本质|PopupBox 的子类|
|典型用途|鼠标悬停、长按、点击信息图标时的轻量说明|
|特点|无标题或极简标题，内容紧凑，常跟锚点位置显示|

示例：PopupBox_HoverInfo、PopupBox_HoverInfo_BattleReport、PopupBox_HoverInfo_SilkRoadFormation
---
4. Pan_ — 面板（两种角色）
Pan_ 有两种用法，需要看上下文：
A. 独立屏幕（侧滑/底部浮层）
|panel_type|说明|
|-|-|
|side_popup_left / side_popup_right|左右侧滑面板，约 600~800 宽|
|bottom_float|底部浮层，高度约 200~600|

B. 子模板/子面板（更常见）
挂在 Menu / PopupBox 内部，通过 TemplateBox 动态实例化，或作为 Tab 子页。
示例：
- 独立：Pan_BattleReport_Page1（战报分页）
- 子模板：Pan_HeroCircleCard、Pan_ArmyMarchHeroCell、Pan_RedPoint_Counter
特点：比 ListItem 更大、更完整，可含 ListBox 和多个交互区；CtrlData 多在 CtrlData/Template/ 下。
---
5. ListItem_ — 列表项模板
|属性|说明|
|-|-|
|容器|挂在 ListBox 里|
|数量|动态（对象池复用）|
|CtrlData|统一在 CtrlData/Template/|
|典型用途|英雄卡片、聊天行、商店商品、部队索引格|

特点：
- 不单独打开，由父界面的 UIListViewEasy / OnListItemShow 驱动
- 支持多模板（同一 ListBox 可注册多种 ListItem）
- 一行数据对应一个 item，适合滚动长列表
示例：ListItem_ArmyMarchSoldierNum2、ListItem_HudCommonChat、ListItem_HeroList_Card
---
6. Hud_ — 常驻 HUD
|属性|说明|
|-|-|
|管理层|ConstantUIManager，场景切换时自动显示/隐藏|
|层级|UILayerCfg.Hud（第 3 层）|
|特点|常驻、高性能约束（禁止重逻辑 OnUpdate）|

示例：
- Hud_Common — 主界面（资源条、按钮组、聊天等）
- Hud_Msg — 通用信息提示
- Hud_Common_Army — 右侧部队队列
特点：不走 Stack/Popup 打开流程，与 3D 场景共存，子组件用 UIWidget 拆分（如 Hud_Common_Top、Hud_Common_Bottom）。
---
7. Float_ — 3D 世界悬浮 UI
|属性|说明|
|-|-|
|基类|UIFloatBase|
|管理层|floatRoot，GetFloatUI / PutFloatUI|
|层级|Float / LowerFloat（1~2 层）|
|典型用途|地图气泡、建筑名、血条、对话气泡、实体 CD|

特点：跟随 3D 坐标或实体，World Space / Screen Space 混合，不阻塞主界面交互。
示例：Float_EntityBubble、Float_DialogBubble、Float_InfiniteZoomName、Float_MapBuildingHpBar
---
8. 其他常见变体
|前缀/名称|特点|
|-|-|
|PopupBox_Dialog_*|剧情对话全屏/半屏|
|PopupBox_MsgBox|二次确认（MessageBox 层）|
|Hud_Msg / Hud_StrongToast|轻提示、强提示（Tips 层）|
|Menu_MarchFloat_*|出征相关全屏变体（带 Float 交互逻辑）|

---
二、层级关系总览
Entity
  UIWidget                    -- 子组件基类
    UIView                    -- 可打开的界面
      Menu_*                  -- 全屏栈 UI
      PopupBox_*              -- 弹窗
      Hud_*                   -- 常驻 HUD
      UIFloatBase
        Float_*               -- 3D 悬浮

  子模板（不独立打开）:
    ListItem_*  -> ListBox 内
    Pan_*       -> TemplateBox 内 或 作为子页
20 层 UILayer 关键层（从低到高）：
LowerFloat -> Float -> Hud -> FullScreen(栈) -> PopupBox -> MessageBox -> Tips -> Loading ...
---
三、容器控件形式（Prefab 内部）
除了 Prefab 前缀，节点上还常用这些容器组件：
ListBox — 滚动列表容器
- 动态数量、对象池、可滚动
- Lua 侧用 UIListViewEasy + OnListItemShow
- 子模板：ListItem_*
---@field m_ListArmyMarchTeam UnityEngine.UI.Extensions.ListBox
---    子控件模板列表: ListItem_ArmyMarchTeamIndex_UGUI_CtrlData
TemplateBox — 固定槽位模板容器
- 编辑器预置位置节点，运行时按数据填充
- 适合少量固定格子（如 5 个兵种位、3 个英雄槽）
- Lua 侧用 UIUtil.RegistTemplateBox
- 子模板：Pan_* 或 ListItem_*
---@field m_PanSoldierNum_01 UnityEngine.UI.Extensions.TemplateBox
---    子控件模板: ListItem_ArmyMarchSoldierNum2_UGUI_CtrlData
Panel / CanvasPanel — 逻辑分组容器
- SetVisible 控制显隐
- CanvasPanel 通常是界面根节点（m_RootPanel）
基础控件
|前缀|组件|用途|
|-|-|-|
|m_Btn|Button|按钮|
|m_Lab|Text|文本|
|m_Pic|Image|图片|
|m_Tog|Toggle|开关/Tab|
|m_Input|InputField|输入框|
|m_Slider|Slider|滑动条|
|m_List|ListBox|列表|
|m_Pan|Panel/LayoutGroup|布局分区|

四、如何选择形式
|场景|推荐形式|
|-|-|
|完整功能页、需压栈返回|Menu_|
|居中确认/规则/奖励|PopupBox_|
|悬停说明、轻提示|PopupBox_HoverInfo_|
|侧滑详情、底部条|独立 Pan_|
|长列表一行一项|ListItem_ + ListBox|
|固定 N 个格子（如 5 英雄位）|Pan_/ListItem_ + TemplateBox|
|主界面常驻元素|Hud_|
|地图上跟实体走的气泡|Float_|
|复杂卡片（含子列表）|Pan_ 子模板|

2. 下载Android Studio
